# CSE4070 · Pintos

서강대학교 2025년 가을학기 운영체제 과제의 제출 소스를 보관하고, 프로세스·스케줄러·가상 메모리 구현을 정리한 저장소입니다. 각 과제는 당시 제출 구조를 유지한 독립적인 소스 트리입니다.

| 과제 | 내용 | 주요 구현 경로 |
| --- | --- | --- |
| PRJ2 | 사용자 프로그램, 프로세스 실행·대기, 파일 시스템 호출 | `prj2/src/userprog/` |
| PRJ3 | 알람, 우선순위 스케줄링·기부, aging, MLFQS | `prj3/src/threads/`, `prj3/src/devices/timer.c` |
| PRJ4 | 지연 로딩, 프레임 교체, 스왑, 메모리 매핑 | `prj4/src/vm/`, `prj4/src/userprog/` |

PRJ4의 기반은 사용자 프로그램 과제이며, PRJ3의 스케줄러 변경은 합쳐져 있지 않습니다. PRJ0·PRJ1은 최종 제출 소스를 확인하지 못해 포함하지 않았습니다.

## 빌드와 실행 검증

최종 QEMU 검증은 **PRJ2 80/80 · PRJ3 30/30 · PRJ4 116/116**, 총 226개 통과입니다.

Docker가 실행 중인 환경에서 다음 명령을 사용합니다. ARM64 Mac과 x86-64 Linux에서 i686 교차 컴파일러로 빌드하고 QEMU로 32비트 Pintos를 실행하도록 구성했습니다. 실제 확인 환경은 [검증 기록](docs/TEST_RESULTS.md)에 적었습니다.

```sh
./tools/run-tests.sh                  # 세 과제 전체
./tools/run-tests.sh prj2              # 사용자 프로그램
./tools/run-tests.sh prj3              # 스레드·스케줄러
./tools/run-tests.sh prj4              # 사용자 프로그램·VM·기본 파일 시스템
```

최초 실행은 Ubuntu 22.04 기반 테스트 이미지를 만듭니다. 테스트는 복사한 소스를 컨테이너 안에서 빌드하며, 결과와 실행 로그는 `test-results/<과제>/`에 저장됩니다. 이 폴더는 Git에 포함하지 않습니다. 호스트 부하가 높으면 `TEST_JOBS=1 ./tools/run-tests.sh prj3`처럼 동시 테스트 수를 줄일 수 있습니다. MLFQS 테스트는 수 분이 걸립니다.

## 정리 내용

- PRJ2: 자식 종료 기록과 대기를 동기화하고, 파일·메모리의 종료 처리를 모았습니다. 사용자 포인터와 쓰기 권한을 검증하며 빠져 있던 파일 삭제 호출을 구현했습니다.
- PRJ3: 인터럽트에서 안전하게 선점하도록 변경하고, 조건 변수와 우선순위 기부의 경합을 수정했습니다. 비어 있던 MLFQS 통계와 우선순위 계산을 구현했습니다.
- PRJ4: 프레임 교체와 해제의 소유권, 스왑 슬롯 수명, 파일 참조 회수를 정리했습니다. `mmap`/`munmap`을 구현하고, 페이지를 고정한 상태에서 사용자 버퍼를 복사하도록 바꿨습니다.

[정리 순서](docs/REFACTOR_PLAN.md)와 [테스트 결과·재현 범위](docs/TEST_RESULTS.md)를 함께 볼 수 있습니다. 최초 제출 파일은 원본 반입 커밋 `40bad57`까지의 이력에 남아 있습니다. 디스크 이미지, 개인 보고서와 제출 압축은 제외했습니다.

기반 Pintos 코드의 저작권 고지와 라이선스는 각 과제의 `src/LICENSE` 및 원본 파일에 보존했습니다.
