# 정리·기능 검증 순서

원본은 최초 10개 반입 커밋에 보존한다. 후속 변경은 `refactor/coursework-cleanup`에서 검토하고, 각 과제의 독립된 소스 구조를 유지한다.

1. **실행 환경 재현**: 같은 Linux 교차 컴파일러와 QEMU에서 원본·수정본의 기존 테스트를 실행한다. 테스트 기대값을 수정해서 통과시키지 않는다.
2. **PRJ2 프로세스·파일 수명**: 자식 생성/대기/종료, 실패한 실행, 부모 종료와 파일 디스크립터 정리를 함께 검토한다. 정리한 제어 흐름을 기존 사용자 프로그램 테스트로 확인한다.
3. **PRJ3 스케줄링**: 인터럽트 문맥의 선점, 우선순위 기부, 조건 변수와 MLFQS를 검토한다. 스레드 전체 테스트를 기준으로 확인한다.
4. **PRJ4 가상 메모리**: 프레임·스왑·보조 페이지 테이블의 소유권, 페이지 교체 중 해제와 메모리 매핑을 점검한다. 사용자 프로그램·VM·기본 파일 시스템 테스트를 함께 실행한다.
5. **결과 기록**: 실제 통과/실패 항목과 재현 명령을 남긴다. 테스트하지 않은 동작까지 완료로 표현하지 않는다.

후속 커밋은 과제별 변경 단위로 나누고, 작성자 날짜와 커미터 날짜 모두 사용자가 지정한 2026년 4~5월의 정리용 날짜로 설정한다.
